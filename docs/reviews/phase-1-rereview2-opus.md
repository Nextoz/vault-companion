## 4. What is sound

- **Create-only and update preconditions.** They are checked against the immutable pinned tree, before any Git object is created, on all three adapters. They are consistent with head-CAS: the precondition, the listing and `base_tree` all refer to the same X, so no interleaving can separate them. A precondition failure is deterministic at X, so returning it as a non-retryable refusal is correct.
- **Fail-closed listing.** A missing directory is confirmed from its parent. Any other 404, a blob in place of a directory, or an unknown commit throws a retryable error. In the P2 emulation I found no input that turns a listing fault into an overwrite.
- **Undoes guard.** The trailer contains IDs only; the target op ID is a zod `uuid` bound to the target's payload hash, so no trailer injection is possible. It does not interfere with the Undo's own idempotent replay, because the replay at `U^` excludes `U`. Two concurrent Undos of one completion serialise through head-CAS, and the loser re-plans into `conflict:task-changed`.
- **Queue generation.** Only a refusal becomes final under the current generation. Receipts always settle. Resends are byte-identical and deduped by the server. Expired claims stay ignored.
- **Reads.** Out-of-order responses are dropped, reflection follows the rendered response, and acknowledgement only permits eviction.
- **Timeout.** The abort is classified as retry. The 30 s timeout is below the 60 s lease, so another tab never takes over an item this tab still considers in flight.
