# O3 real-queue e2e — handoff

**Completed.** New Playwright project `pixel-7-chromium-real-stack` (`apps/web/playwright.config.ts`, spec `e2e/real-stack.spec.ts`, fixture `e2e/real-stack.ts`). Each test gets its own origin: `StaticServer` serves `dist/` and forwards `/api/*` to the packages/e2e harness server (real `createApp` + command service + `LocalGitStore` on a temp bare repo). The gateway adds the harness's locally signed Access JWT, like the Access edge. Its only fault is holding a command response the server already produced. Flows: (1) 26 offline actions (10 completions, 8 task captures, 8 note captures) → online → 26 commits, one per op → 20 kept after eviction, all acknowledged (Clear saved empties the list) → exact To-Do bytes + each Inbox note once; (2) complete, then Undo while the completion receipt is held → 1 completion + 1 undo commit, file == seed, task back in Today; (3) desktop edit + phone completion → W4 sync commits markers → banner, no Complete, Task capture disabled → desktop resolves + syncs → banner gone, completion lands byte-exact.
Harness changes (minimal): `startServer({ appOrigin? })` (default `APP_ORIGIN`); `StaticServer` gets an optional `/api` handler, and `close()` now calls `closeAllConnections()`. `tsconfig.tools.json` references `packages/e2e`.

**Discoveries.** (a) The queue orders only actions on the same task: independent offline captures sometimes land out of order (seen 1 in 3 runs). Flow 1 therefore reads the order back from the file and checks the lines as a set, with exact bytes otherwise. (b) Teardown hung >30 s because the open page kept keep-alive connections to `StaticServer`. Fixed with `closeAllConnections()`.

**Guard mutations (each restored; each made its flow fail):** F1 `queue.acknowledge` never marks a receipt acknowledged → list stuck at 26, expected 20. F2 draft token filled with `draft.baseRevision` instead of the completion's commit → Undo never saved (1 of 2). F3 `taskListLock` always returns null → conflict banner not found.

**Recommend.** `pnpm --filter web e2e` now also runs this project (needs Chromium, which CI already installs). Consider WebKit later; offline emulation for it is untested here. If captures should keep device order across tasks, that needs its own decision (ADR); today it is not a guarantee.
