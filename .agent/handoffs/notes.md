Discoveries / choices for the Lead:
1. Header values must be ASCII, but note names often aren't (æøå). I added `NOTE_HEADER`, `encodeNoteHeader` (encodeURIComponent) and `decodeNoteHeader` to contracts. `InboxNotePath` rejects `%`, so decoding is unambiguous.
2. Edit reads the file without re-listing Inbox/ (saves a subrequest). Symlink safety relies on the `expect: 'regular-file'` write precondition plus blob CAS. Add a `listFiles` check if you want it at plan time too.
3. Title keeps a collision suffix (`X (2)`), and sorting within a date is by title, so `X` comes before `X (2)`. An invalid date suffix (e.g. 02-30) counts as undated.
4. Final newline: a file without one never gains one, so trailing line breaks typed into the editor are dropped. The ADR doesn't cover new-body NUL (refused as `invalid`) or lone surrogates (refused as `refused:encoding`); both are my own additions.
5. Not refused: a body typed into a note that has no frontmatter, and that starts with a `---` block, becomes frontmatter on the next read.
6. Web allows a second edit only after a read contains the first (`canStartEdit`), so it never re-sends from a stale blob. Edits of one note share the queue key `note:<path>`.
7. The new "Notes" tab collided with the capture sheet's "Note" button, so the `name: 'Note'` locators in app.spec/draft.spec are now `exact: true`.
