## Spec gaps / ambiguities and how they were resolved

1. **Final-newline ambiguity (F16) vs exact inverse.** Removing the last line of a no-final-newline file yields
   bytes (`…## Open\n`) that re-parse as "has final newline". The exact inverse therefore tries both line-model
   readings and accepts a candidate only if **re-completing it reproduces the current file byte for byte** (this
   also settles whether completion inserted a blank line, which `CompleteEffect` does not record). If no candidate
   verifies, it falls back to the semantic inverse.
2. **Semantic inverse blank-line count** when the desktop removed blank lines: uses `min(recorded, present)`,
   never adds blank lines (§4 "blank lines are never added…"). The blank line that a completion inserted into an
   empty Done is left in place by the semantic inverse (no rule removes it).
3. **Top-of-Open when the first non-blank Open line is indented** (new with D4): the captured task would adopt that
   line as a child ⇒ `refused:structure` for capture and for the Undo fallback.
4. **Capture text that opens a comment** (`%%`, `<!--` unclosed) would hide the rest of the file from Obsidian ⇒
   `refused:structure`; balanced inline `%%x%%` is allowed. Implemented generically: capture is refused if any
   other line's visibility changes.
5. **Open task already carrying a trailing `✅`/`❌`** ⇒ `readOnlyReason: refused:duplicate-field` (completion would
   add a second field of the same kind).
6. **Task block ending inside a fence/comment it opened** ⇒ `readOnlyReason: refused:structure` (moving it would
   re-interpret later lines).
7. **`readOnlyReason`** is set only for the four §2 reasons plus 5/6 above; done/cancelled tasks get `null` there and
   `completeTask` returns `refused:already-completed`. Precedence: unsupported-status > duplicate-field > recurring >
   on-completion > structure.
8. **Conflict markers**: spec regexes plus a bare `<<<<<<<`/`>>>>>>>`/`|||||||` at end of line (strict superset,
   more refusals only). Detected anywhere, including inside fences.
9. **Unclosed frontmatter** is not frontmatter (Obsidian behaviour); an **unclosed fence** hides the rest of the file
   (CommonMark), which surfaces as `refused:structure` rather than a guess.
10. **Duplicate `## Done` on read**: tasks of the unique `## Open` are still returned for display (with
    `writeBlock`); nothing is attributed to an ambiguous section.
11. **Completed-in-place effect**: `anchorBefore: ''`, `blankLinesAfterAnchor: 0`, `insertedAt = removedAt`.
12. **Note titles also drop `%`**: `parseVaultPath` rejects any path containing `%`, so a spec-conformant title
    such as "50% done" would make note capture fail. Deviation from the §4.5 list; please confirm or amend §4.5.
13. **Casefold** is approximated as NFC + `toUpperCase().toLowerCase()` (ß ⇒ ss). This over-matches, and the only
    effect of over-matching is an unnecessary ` (n)` suffix, never an overwrite.
14. `blockId` is exposed without the `^`; tags include the `#`; `links` skip empty targets (`[[#heading]]`).
15. **Encoding**: the kernel takes decoded strings, so it can only detect lone surrogates. Adapters must decode
    with `new TextDecoder('utf-8', { fatal: true, ignoreBOM: true })` (fatal ⇒ `refused:encoding`, ignoreBOM ⇒
    BOM preserved). `test-vault` does exactly this. `lib: ES2023` without DOM types is why the kernel does not
    export such a helper.
16. **Contracts gap**: the `Context` zod regex in `packages/contracts` allows U+2028/U+2029/U+0085/NUL inside a
    `[[wikilink]]`. The kernel re-validates and throws `TypeError`, but contracts should reject these up front.

## Proposed `api.ts` changes (not applied)

- Add `'invalid'` to `RefusalCode`. Today an empty-after-sanitisation capture throws `RangeError`, and a malformed
  date/context or a NUL in note text throws `TypeError`. The domain must pre-validate these (or catch) until this
  is added.
- Optionally add `insertedBlankLine: boolean` to `CompleteEffect`. Not required (see gap 1), but it would make the
  exact inverse explicit rather than verified by re-completion.

## Follow-up (Lead review)

- `api.ts`: `'invalid'` added to `RefusalCode`.
- `completeTask` returns `invalid` for a malformed `doneDate`. `captureTask` returns `invalid` for a malformed
  `createdDate`/`due`, a malformed `context` (shape, control or separator chars, lone surrogates) and text that is
  empty after sanitisation. None of these throw any more.
- `noteFileName` and `renderNote` return `string` by signature, so they cannot return a Refusal and still throw
  `TypeError` on bad input. New non-throwing `checkNoteInput(input): Refusal | null` (exported) covers every case
  `renderNote` rejects: `invalid` for date/`capturedAt`/context/NUL, `refused:encoding` for ill-formed text. The
  domain should call it first; `renderNote` uses it internally, so the two cannot drift.
- `KernelInvariantError` is unchanged (still a throw: bug signal).
- Tests: the throw expectations became `invalid` refusal assertions, and cases were added for empty and
  whitespace-only text, `due`, and more context shapes. `checkNoteInput` has its own test. Total **176 tests**, lint and
  typecheck green.
- Merge note: domain code on `main` that switches exhaustively over `RefusalCode` must handle `'invalid'`
  (maps 1:1 to the contracts `ErrorCode` `'invalid'`).
