Reviewer: independent fresh-context session (did not author the design). Date: 2026-09-24.
Scope: the brief `docs/reviews/phase-0-architecture-review-brief.md` — all listed contracts, ADR-0001…0009,
`docs/plan.md`, discovery findings, spike script + output, bootstrap §2–3, §10–11, §13 Phase 0–2.
Not opened: the reference vault. No files changed except this report.

Severity: **Critical** = a duplicate/lost durable effect or wrong-task write reachable under realistic
conditions by following the contract as written. **High** = data loss/corruption or a first-release
acceptance statement that cannot hold as specified. **Medium** = a real failure mode needing a contract
change before the relevant phase. **Low** = clarification, test gap, hygiene.

## What is sound

- **Source of truth.** ADR-0001, `sync.md` and the product contract say the right thing consistently:
  GitHub `main` is a durable remote endpoint, "Saved to GitHub" is the strongest claim, desktop receipt
  and worker health are explicitly never claimed, Drive is off the app path, no second store. Apart from
  F10 (wording of *saving*, stale re-reads) and F17 (Drive as a potential desktop-side writer), I found no
  path where a cache or Drive becomes authoritative.
- **Git trailers as idempotency evidence** (ADR-0005) is the right primitive — restart-safe, no database,
  proven locally (S8). The defect (F1) is ordering, not the idea; with the read pinned to one commit, blob
  CAS makes same-file and create races airtight.
- **Exact-content locator** with blob-pinned line index is a sensible first-release identity; refusing
  `🆔` writes until a feature needs them avoids a vault convention change. It needs F2's duplicate rule.
- **Span-splice, per-file EOL detection, no normalisation, typed refusals**, and a hand-written line
  scanner (ADR-0004) fit the line-oriented task grammar. Mirroring Tasks' trailing-field rule (including
  non-trailing markers staying description) is correct and grounded in the shipped bundle.
- **Recurrence refused** rather than half-implemented; Done never trimmed; Done today derived from
  Markdown with explicit Copenhagen/IANA date rules and a skew window.
- **Security baseline** covers every §3.8 heading: Access + independent JWT verification, JSON-only +
  custom header + Origin, path policy in two layers, raw-HTML-off rendering with strict CSP, `no-store`,
  SW caching shell only, short-lived App tokens, allowlisted logger with a sentinel test, previews and
  source maps. Gaps are F11, F12, F20.
- **Scope discipline.** No D1, Durable Objects, TanStack, AI or journal; each deferral has a trigger.
  Additions beyond bootstrap §2 are small and justified (read-only Active Work Now as context; `ReopenTask`
  specified but not exposed; `backdated` flag). Missing vs §3.4: optional context on `CaptureTask`
  (only `CaptureNote` has it) — cheap to add now to avoid a storage-model change later.
- **Phase 0 deliverables** are present (env check, snapshot-freshness discrepancies recorded honestly,
  conventions, old worker analysed with a real-Git spike that found the S4/S5 blocking and S5b conflict,
  contracts, ADRs, threat model, fixture requirements, acceptance + canary evidence). Not delivered:
  live probing of GitHub write/compare behaviour (gated on G1 — see F15) and a consolidated
  unresolved-risk list (risks are spread across findings §Consequences, `sync.md` and plan D1–D4).

## Verdict

**PASS WITH FIXES**

The architecture direction is sound, and every finding is fixable in the documents before code exists.
The conditions for starting Phase 1 delegation are: F1 (dedupe/read pinned to one commit, with the failing
test named), F2, F3, F4/F5 (Undo by target operation ID, server-derived effect, dependent queue ordering),
F6 (conflict-marker refusal now; D4 promoted to a pre-Phase-2 owner decision) and F7 are reflected in
`commands.md`, `vault-contract.md`, the ADRs and `testing.md`, and F15's G1 request is put to the owner.
Mediums before the phase they affect; Lows at the Lead's discretion.
