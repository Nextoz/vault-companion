## What is sound

- **Executor** (`execute.ts`): there is one X per attempt. Dedupe runs before the read. An unknown outcome is never resent blindly; it re-dedupes. A lost CAS re-dedupes against a newer X. `unknown` never writes. The `already-applied` effect is re-derived by replay on `C^` with byte equality (F5). I found no duplication path, including stale-head re-reads: blob CAS and create-without-sha catch them.
- **Undo authentication**: the target is found by trailer, its payload hash is checked over the *raw* target envelope (JCS), and the effect is server-derived. The client never supplies an effect.
- **Kernel byte fidelity on the happy paths**: BOM kept through `ignoreBOM` and `splitDoc`. Lone-CR and mixed EOL refused. The F16 final-newline handling in `joinDoc` and the double reading in the exact inverse are correct. Completion and capture both carry strong post-condition invariants, including the capture "reading of the rest of the file is unchanged" check against unclosed `%%`/`<!--`. The fuzz run found no byte changes outside the intended span for complete or capture.
- **Refusals**: conflict markers block every write, including a bare marker line. Recurring, on-completion, duplicate-field and unsupported-status are enforced before any splice. An open task that already has `✅`/`❌` is refused (no second `✅`).
- **Locator** (§3/F2): the twins rule is implemented as specified, and `occurrencesAtRead > 1` with a changed blob gives `ambiguous`.
- **Worker**: the Access JWT is verified independently (RS256 only, iss, aud, exp, email allowlist, `sub` required). Origin, `X-VC-Request` and the JSON content type are enforced on the only mutating route. The config guard fails closed with a detail-free 503. The log record is allowlisted by type and at runtime, and paths are logged only as a hash. Validation errors never echo values.
- **Contracts**: strict objects everywhere, 40-hex SHAs, UUID operation IDs (safe to log), capture context rejects control and separator characters.
- **Queue**: the envelope is persisted before the first send, and `everSent` is set before the request leaves. The identical stored body is resent. Sends are gated on account binding and pause on signed-out. Discard is refused while a request is in flight.

## Verdict

**PASS WITH FIXES.** Fix R1 and R2 in the kernel, with golden and property tests, before the first live write. Fix R3 and R4 before the PWA queue carries real undos. R5 restores a security.md requirement. The Low findings can follow in Phase 2.
